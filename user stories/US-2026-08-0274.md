Move Zero-Quantity BOQ and Contract Items to `Items With Zero Qty`


User Story


As a construction user, I need BOQ and Contract rows with `Quantity` equal to `0` to be separated into a dedicated child table, so zero-quantity scope stays visible for review while normal BOQ and Contract item rows continue through the standard process.


Business Requirement


Add a checkbox in `Construction Settings` labeled `Move Zero Quantity Items on Submit`.


When the checkbox is enabled, BOQ submit must move rows where `Quantity` is exactly `0` from `Bill of Quantity` into a BOQ child table labeled `Items With Zero Qty`.


When the checkbox is unchecked, BOQ submit must be blocked if any row in `Bill of Quantity` has `Quantity` equal to `0`.


When a `Construction Contract` is created from that BOQ, the zero-quantity BOQ rows must be copied into a Contract child table also labeled `Items With Zero Qty`.


When Contract items are uploaded, the system must detect uploaded rows where `Quantity` is `0` and place them in Contract `Items With Zero Qty`, not in the original Contract `items` table.


Duplicate prevention must use `BOQ` + `BOQ Child` as the row identity.


Expected Behavior


When `Move Zero Quantity Items on Submit` is enabled:


    User submits a draft `BOQ`.
    System checks all rows in `Bill of Quantity`.
    Rows where `Quantity` is greater than `0` remain in `Bill of Quantity`.
    Rows where `Quantity` is exactly `0` are moved to BOQ `Items With Zero Qty`.
    Moved zero-quantity rows are removed from `Bill of Quantity` before submit completes.
    BOQ submit continues if no other validation blocks the document.
    When a `Construction Contract` is created from the BOQ, the BOQ zero-quantity rows are copied into Contract `Items With Zero Qty`.
    The same `BOQ` + `BOQ Child` row must not exist in both Contract `items` and Contract `Items With Zero Qty`.


When `Move Zero Quantity Items on Submit` is unchecked:


    User submits a draft `BOQ`.
    If any row in `Bill of Quantity` has `Quantity` equal to `0`, submit is blocked.
    The user sees a clear validation message identifying the affected rows.
    Zero-quantity rows remain in `Bill of Quantity`.


For Contract upload:


    User uploads Contract item rows.
    Rows where `Quantity` is greater than `0` are placed in the original Contract `items` table.
    Rows where `Quantity` is exactly `0` are placed in Contract `Items With Zero Qty`.
    Every uploaded row must have the needed `BOQ` and `BOQ Child` reference for duplicate prevention.
    A row with the same `BOQ` + `BOQ Child` must not exist in both Contract item tables.

Add a Check field in `Construction Settings`:


    label: `Move Zero Quantity Items on Submit`
    suggested fieldname: `move_zero_quantity_items_on_submit`
    default: unchecked


Add a child table in `BOQ`:


    label: `Items With Zero Qty`
    suggested fieldname: `items_with_zero_qty`
    purpose: store rows moved from `Bill of Quantity` where `Quantity` is `0`


Add a child table in `Construction Contract`:


    label: `Items With Zero Qty`
    suggested fieldname: `items_with_zero_qty`
    purpose: store zero-quantity rows copied from BOQ or detected during Contract upload


BOQ submit logic:


    Read `Move Zero Quantity Items on Submit` from `Construction Settings`.
    Find all `bill_of_quantity` rows where `qty == 0`.
    If enabled, move those rows into BOQ `Items With Zero Qty` and remove them from `bill_of_quantity`.
    If unchecked, block submit and show the zero-quantity row numbers.
    Keep negative `Quantity` blocked.


Contract creation from BOQ:


    Copy positive-quantity BOQ rows into Contract `items`.
    Copy BOQ zero-quantity rows into Contract `Items With Zero Qty`.
    Use `BOQ` + `BOQ Child` to identify each source row.
    Do not copy the same `BOQ` + `BOQ Child` row into both Contract tables.


Contract upload behavior:


    Require uploaded rows to carry `BOQ` and `BOQ Child` references.
    Detect uploaded rows where `Quantity` is `0`.
    Put zero-quantity uploaded rows into Contract `Items With Zero Qty`.
    Put only positive-quantity uploaded rows into the original Contract `items` table.
    Block the upload or save if the same `BOQ` + `BOQ Child` exists in both tables.


Quantity rule:


    In BOQ `Items With Zero Qty`, `Quantity` must always be `0`.
    In Contract `Items With Zero Qty`, `Quantity` must always be `0`.
    Users must not be able to edit `Quantity` in either zero-quantity table.
    Server-side validation must enforce zero quantity even if the value is changed through upload, API, import, or script.


Validation and calculation rule:


    Contract `Items With Zero Qty` must run the same applicable validation and calculation behavior already used by the original Contract `items` table.
    The only functional exception is that `Quantity` is fixed at `0` and cannot be edited.
    Amount, tax, rate, allocation, reference, and total behavior affected by zero quantity must remain consistent with the existing Contract item rules.


Acceptance Criteria


    `Construction Settings` has a Check field labeled `Move Zero Quantity Items on Submit`.
    `BOQ` has a child table labeled `Items With Zero Qty`.
    `Construction Contract` has a child table labeled `Items With Zero Qty`.
    When the checkbox is enabled, BOQ submit moves rows where `qty == 0` from `Bill of Quantity` to BOQ `Items With Zero Qty`.
    When the checkbox is enabled, moved zero-quantity rows no longer remain in `Bill of Quantity` after submit.
    When the checkbox is unchecked, BOQ submit is blocked if zero-quantity rows exist in `Bill of Quantity`.
    Creating a Contract from BOQ copies BOQ zero-quantity rows into Contract `Items With Zero Qty`.
    Contract upload detects zero-quantity rows and places them in Contract `Items With Zero Qty`.
    Duplicate prevention between Contract `items` and Contract `Items With Zero Qty` uses `BOQ` + `BOQ Child`.
    The same `BOQ` + `BOQ Child` cannot exist in both Contract item tables.
    `Quantity` in both zero-quantity tables is always `0` and cannot be edited by the user.
    Server-side validation blocks any non-zero `Quantity` inside either zero-quantity table.
    Existing validation and calculation behavior for Contract item rows is applied to Contract `Items With Zero Qty`, except for quantity editing.
    Negative `Quantity` remains blocked.


Related Behavior Risk


Moving rows out of original BOQ and Contract item tables can affect totals, Contract creation, invoices, variation orders, reports, validations, and duplicate checks that currently read only the original item tables.


The implementation must update submit, create-from-BOQ, upload, validation, calculation, and duplicate-check paths so zero-quantity rows are handled consistently.

Testing Procedure


Preconditions and test data:


Create BOQ and Contract test data with positive, zero, and negative `Quantity` rows. Include rows linked by `BOQ` and `BOQ Child`.


Execution steps:


Enable `Move Zero Quantity Items on Submit`, submit a BOQ with zero-quantity rows, then create a Contract from that BOQ.


Expected result:


Zero-quantity rows move to BOQ `Items With Zero Qty`, are removed from `Bill of Quantity`, and are copied to Contract `Items With Zero Qty`. They do not appear in the Contract original `items` table.


Execution steps:


Disable `Move Zero Quantity Items on Submit`, then submit a BOQ with zero-quantity rows.


Expected result:


BOQ submit is blocked, zero-quantity rows remain in `Bill of Quantity`, and the validation message identifies the affected rows.


Execution steps:


Upload Contract rows with positive and zero quantities, including `BOQ` and `BOQ Child` references.


Expected result:


Positive rows go to Contract `items`. Zero-quantity rows go to Contract `Items With Zero Qty`. No `BOQ` + `BOQ Child` combination exists in both tables.


Negative and regression checks:


Negative `Quantity` must always be blocked. Users must not be able to edit `Quantity` in either `Items With Zero Qty` table. Attempts to save non-zero quantity through upload, API, import, or script must be blocked. Positive-only BOQs and Contracts must continue working normally.


Evidence to verify:


Verify checkbox value, BOQ status, Contract status, original item table rows, `Items With Zero Qty` rows, `Quantity` values, duplicate validation messages, submit validation messages, and calculated totals.
