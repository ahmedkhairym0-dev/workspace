Update Zero-Quantity Items Through BOQ and Contract Variation Orders


User Story


As a construction user, I need a controlled Variation Order process to activate items that were previously stored in `Items With Zero Qty`, so users can update the quantity and allocation before those items move into the main BOQ or Contract item tables.


Business Requirement


Add a new type called `Update Zero Qty Items` for:


    `BOQ Variation Order`
    `Variation Order` for `Construction Contract`


This type is used only for items that currently exist in `Items With Zero Qty`.


For BOQ, the system must map rows from BOQ `Items With Zero Qty` into the BOQ Variation Order main child table.


For Contract, the system must map rows from Contract `Items With Zero Qty` into the Contract Variation Order main child table.


Users must not keep these rows with `Quantity` equal to `0`. They must either update the quantity or confirm that unchanged zero-quantity rows should be deleted from the Variation Order before submit.


Expected Behavior


For `BOQ Variation Order` with type `Update Zero Qty Items`:


    User creates a BOQ Variation Order from a BOQ.
    User selects type `Update Zero Qty Items`.
    System maps rows from BOQ `Items With Zero Qty` into the BOQ Variation Order main child table.
    User can edit only:
     - `Quantity`
     - `Type Of Allocation` 
     - the allocation value related to the selected `Type Of Allocation`
    User cannot submit rows where `Quantity` remains `0`.
    If rows still have `Quantity` equal to `0`, system shows a confirmation message asking whether to delete those unchanged rows from the Variation Order.
    After BOQ Variation Order submit, updated rows are moved from BOQ `Items With Zero Qty` into the main BOQ `Bill of Quantity` table.
    For `Construction Settings`.construction_item_be_text == true, item_code_text must be unique If the same `Item Code` and same `allocation` already exist in the main BOQ table, update the existing row quantity by addition quantities instead of adding a new row.
    The item must be removed from BOQ `Items With Zero Qty` in both cases:
     - when it is added as a new main BOQ row
     - when it updates an existing main BOQ row


For Contract `Variation Order` with type `Update Zero Qty Items`:


    User creates a Contract Variation Order from a `Construction Contract`.
    User selects type `Update Zero Qty Items`.
    Before creating the Contract Variation Order, system must confirm the related item has already been moved from BOQ `Items With Zero Qty` into the main BOQ `Bill of Quantity` table.
    System maps rows from Contract `Items With Zero Qty` into the main Contract Variation Order item table.
    User can edit `Quantity` only.
    User cannot submit rows where `Quantity` remains `0`.
    If rows still have `Quantity` equal to `0`, system shows a confirmation message asking whether to delete those unchanged rows from the Variation Order.
    User cannot enter a quantity greater than the remaining quantity available in BOQ.
    After Contract Variation Order submit, updated rows are moved from Contract `Items With Zero Qty` into the main Contract `items` table.
    If the same `BOQ` + `BOQ Child` already exists in the main Contract `items` table, update the existing row quantity by addition quantities instead of adding a new row.
    The item must be removed from Contract `Items With Zero Qty` in both cases:
     - when it is added as a new main Contract item row
     - when it updates an existing main Contract item row


Developer Section


Affected app: `fabrica_construction`


Affected DocTypes:


    `BOQ`
    `BOQ Child`
    `BOQ Variation Order`
    `BOQ Variation Order Items`
    `Construction Contract`
    `Construction Contract Items`
    `Variation Order`
    `Variation Order Items`
    BOQ child table `Items With Zero Qty`
    Contract child table `Items With Zero Qty`


Current source notes:


    `BOQ Variation Order` currently uses child table `bill_of_quantity` with child DocType `BOQ Variation Order Items`.
    Contract `Variation Order` currently has `variation_order_type`, but its options do not include `Update Zero Qty Items`.
    Existing Contract VO validation dispatch handles `Update Current Contracted BOQ`, `Update New Scope`, and `Retroactive Change Rate`; it must be extended for `Update Zero Qty Items`.


Add BOQ Variation Order type:


    Add/select type value: `Update Zero Qty Items`
    The create action from BOQ must support this type.
    For this type, map BOQ `Items With Zero Qty` rows into BOQ Variation Order `bill_of_quantity`.


Add Contract Variation Order type:


    Add option `Update Zero Qty Items` to Contract `Variation Order Type`.
    The create action from Contract must support this type.
    For this type, map Contract `Items With Zero Qty` rows into the main VO item table.


BOQ submit behavior for `Update Zero Qty Items`:


    Validate that each submitted row has `Quantity` greater than `0`.
    If any row still has `Quantity` equal to `0`, ask user to confirm deleting those unchanged rows from the Variation Order.
    Move valid updated rows from BOQ `Items With Zero Qty` to BOQ `Bill of Quantity`.
    If same `Item Code` and same allocation already exist in BOQ `Bill of Quantity`, update the existing row quantity.
    If no matching main BOQ row exists, add a new row.
    Remove processed rows from BOQ `Items With Zero Qty`.


Same BOQ item rule:


Same item means same `Item Code` and same allocation value.


The allocation value depends on `Type Of Allocation`:


    `Project` means same `project`
    `Zone` means same `zone`
    `Building Type` means same `building_type`
    `Building` means same `building_number`
    `Floor` means same `floor`
    `Unit` means same `unit`


Contract creation rule for `Update Zero Qty Items`:


    Before creating the Contract VO, check that the related item already exists in BOQ `Bill of Quantity`.
    If the item is still only in BOQ `Items With Zero Qty`, block Contract VO creation.
    This prevents Contract quantities from being updated before the BOQ is updated.


Contract submit behavior for `Update Zero Qty Items`:


    Validate that each submitted row has `Quantity` greater than `0`.
    Validate that `Quantity` does not exceed the BOQ remaining quantity.
    If any row still has `Quantity` equal to `0`, ask user to confirm deleting those unchanged rows from the Variation Order.
    Move valid updated rows from Contract `Items With Zero Qty` to Contract `items`.
    If the same `BOQ` + `BOQ Child` already exists in Contract `items`, update the existing row quantity.
    If no matching main Contract row exists, add a new row.
    Remove processed rows from Contract `Items With Zero Qty`.


Cancel / unsubmit behavior:


    If an `Update Zero Qty Items` Variation Order is canceled after submit, the system must reverse the movement.
    BOQ rows moved by the BOQ Variation Order should return to BOQ `Items With Zero Qty` or reduce the quantity added to the main BOQ row.
    Contract rows moved by the Contract Variation Order should return to Contract `Items With Zero Qty` or reduce the quantity added to the main Contract row.
    The reversal must use the original source reference, not only `Item Code`.


Acceptance Criteria


    `BOQ Variation Order` supports type `Update Zero Qty Items`.
    Contract `Variation Order` supports type `Update Zero Qty Items`.
    BOQ `Update Zero Qty Items` maps rows from BOQ `Items With Zero Qty` into BOQ Variation Order main child table.
    Contract `Update Zero Qty Items` maps rows from Contract `Items With Zero Qty` into Contract Variation Order main child table.
    BOQ Variation Order allows editing only `Quantity`, `Type Of Allocation`, and the selected allocation value.
    Contract Variation Order allows editing only `Quantity`.
    Rows with `Quantity` still equal to `0` cannot be submitted as active rows.
    System shows confirmation before deleting unchanged zero-quantity rows from the Variation Order.
    BOQ submit moves updated rows from BOQ `Items With Zero Qty` to BOQ `Bill of Quantity`.
    Contract submit moves updated rows from Contract `Items With Zero Qty` to Contract `items`.
    Existing main-table rows are updated instead of duplicated when the same item already exists.
    Processed rows are removed from `Items With Zero Qty`.
    Contract VO creation is blocked if the related BOQ item has not already been moved into BOQ `Bill of Quantity`.
    Contract VO quantity cannot exceed BOQ remaining quantity.
    Cancel / unsubmit reverses the submitted movement.


Related Behavior Risk


This affects BOQ totals, Contract totals, remaining BOQ quantity, Contract item quantity, invoices, variation orders, and reports that read from the main item tables.


The developer must update create, submit, cancel, validation, calculation, and duplicate-check paths for both BOQ Variation Order and Contract Variation Order.


Testing Section


Test these flows:


    Create BOQ Variation Order type `Update Zero Qty Items`.
    Submit BOQ Variation Order after updating zero-quantity item quantity.
    Submit BOQ Variation Order where an updated item already exists in main BOQ table.
    Try to submit BOQ Variation Order while item quantity remains `0`.
    Create Contract Variation Order type `Update Zero Qty Items`.
    Block Contract Variation Order creation when BOQ item is still not moved to main BOQ table.
    Submit Contract Variation Order after updating quantity.
    Submit Contract Variation Order where the item already exists in main Contract `items`.
    Validate Contract quantity against BOQ remaining quantity.
    Cancel / unsubmit submitted BOQ and Contract Variation Orders.


Testing Procedure


Preconditions and test data:


Create a BOQ with rows in `Items With Zero Qty`. Create a Construction Contract from that BOQ so matching zero-quantity rows exist in Contract `Items With Zero Qty`.


Execution steps:


Create a BOQ Variation Order with type `Update Zero Qty Items`. Update one row quantity from `0` to a positive value and submit.


Expected result:


The row moves from BOQ `Items With Zero Qty` to BOQ `Bill of Quantity`. BOQ totals are recalculated.


Execution steps:


Create another BOQ Variation Order where the same `Item Code` and same allocation already exist in BOQ `Bill of Quantity`.


Expected result:


The existing BOQ row quantity is updated. No duplicate BOQ row is created. The row is removed from BOQ `Items With Zero Qty`.


Execution steps:


Create a BOQ Variation Order and leave one mapped row with `Quantity` equal to `0`.


Expected result:


System shows a confirmation message to delete the unchanged zero-quantity row. The row cannot be submitted as an active updated item.


Execution steps:


Create a Contract Variation Order with type `Update Zero Qty Items` before the related item is moved into BOQ `Bill of Quantity`.


Expected result:


System blocks creation and tells the user the BOQ item must be updated first.


Execution steps:


After BOQ is updated, create a Contract Variation Order with type `Update Zero Qty Items`. Update quantity and submit.


Expected result:


The row moves from Contract `Items With Zero Qty` to Contract `items`. If the same `BOQ` + `BOQ Child` already exists in Contract `items`, the existing row quantity is updated instead of adding a duplicate row.


Negative and regression checks:


Confirm users cannot submit rows with `Quantity` equal to `0`. Confirm Contract quantity cannot exceed BOQ remaining quantity. Confirm normal BOQ Variation Order and Contract Variation Order types still work as before. Confirm cancel / unsubmit reverses the movement correctly.


Evidence to verify:


Verify Variation Order type, source table rows, target main table rows, deleted unchanged rows, updated quantities, allocation values, BOQ remaining quantity, recalculated totals, validation messages, and document status.
