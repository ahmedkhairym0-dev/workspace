BOQ Items Resources rows can contain item_code and master_item while Item Resources Name and Master Item Name remain blank. The audit confirmed 15,465 affected rows across 36 additional BOQs. The existing patch targets only the originally reported BOQ.


Ensure resource generation populates item_resources_name from item_code.item_name and master_item_name from master_item.item_name, both referencing Construction Item. Cover all BOQ resource creation and restoration paths, including draft resource generation, New Scope additions and restoration from an active Delete log when cancelling a BOQ Variation Order. Population must work for legacy BOQs with custom_old_data enabled without removing their existing validation exceptions.


Deliver a registered migration patch covering all existing BOQs, including draft, submitted and cancelled records. Treat null, empty and whitespace-only names as missing. Repair each field independently and preserve populated names.

## SQL query 

```sql
SELECT JSON_OBJECT(

    'boq', resource.parent,

    'missing_item_resources_name', SUM(CASE WHEN TRIM(COALESCE(resource.item_resources_name, '')) = '' THEN 1 ELSE 0 END),

    'missing_master_item_name', SUM(CASE WHEN TRIM(COALESCE(resource.master_item_name, '')) = '' THEN 1 ELSE 0 END),

    'rows_with_missing_names', COUNT(*)

) AS result

FROM `tabBOQ Items Resources` resource

WHERE resource.parenttype = 'BOQ'

  AND resource.parentfield = 'boq_items_resources'

  AND resource.parent <> 'BOQ--18345'

  AND (

      TRIM(COALESCE(resource.item_resources_name, '')) = ''

      OR TRIM(COALESCE(resource.master_item_name, '')) = ''

  )

GROUP BY resource.parent

ORDER BY resource.parent
```


## Acceptance Criteria 

- Draft resource generation: Given a draft BOQ using item resources and linked Construction Item records with nonblank item_name values, generate its resources, save and reload it. Both resource name fields match their respective linked item names.

- New scope resources: Given a submitted BOQ using item resources and a new scope item with defined resources, submit a BOQ Variation Order adding that scope. After reloading the BOQ, each newly created resource row contains both linked item names. Repeat with custom_old_data enabled and disabled; resource quantities, rates, amounts and duplicate prevention retain their existing results.

- Historical backfill: Given existing resource rows with both names missing or only one missing, run the patch across draft, submitted and cancelled BOQs. Each missing field is populated from its own linked Construction Item.item_name; existing populated names remain unchanged.

- Unresolvable names: Given a missing link, an unresolved linked record or a linked item with a blank item_name, run the patch. Repair any independently resolvable field, leave the unresolved field unchanged, and report the BOQ, resource row, field and reason without inventing a name or changing links.

- Controlled repair: Run a dry run before applying the patch. It reports proposed changes and unresolved rows without writing data. Applying the patch records before/after name values and changes only the two name fields; row identities, links, document statuses, quantities, rates, amounts and contracted or invoiced values remain unchanged.

- Repeatability and verification: Run the patch again after a successful repair. It makes no further changes. A final audit finds no missing names where the corresponding linked item has a usable name, and reports all remaining unresolved rows. In a developer-automated test, inject a failure during an update transaction and verify that its writes roll back and the failure is reported.

- Restored resource names: In a developer-automated test, prepare a submitted BOQ using item resources with custom_old_data enabled and a submitted BOQ Variation Order using Update Current BOQ. Its single variation-order row retains the removed BOQ item's identifier in boq_child and has a matching active Delete log for this BOQ, variation order and row. The log contains the removed BOQ item and resource rows with both name fields blank, while the linked Construction Item records have nonblank item_name values. Run the backfill first, then cancel the variation order and reload the BOQ. The restored resource rows reference the restored BOQ item, and both name fields match their respective linked item names.
