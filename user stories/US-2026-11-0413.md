Enable users across all clients to maintain child-table data through separate Excel-template controls in each Design child table. The required workflow supports .xlsx round trips that update matching rows, add permitted new rows, and retain rows omitted from the spreadsheet.



Implement in fabrica_construction, reusing its spreadsheet utilities and extending Construction Export Template to support both Design DocTypes.



Required Behavior



Provide separate Download and Upload controls for every child table in both DocTypes, including these current tables:


Parent DocType	Child tables
Design Contract	Items, Purchase Taxes and Charges
Design Invoice	Items, Advances, Purchase Taxes and Charges


Download produces a table-specific .xlsx file using a selectable template, with current rows or a Blank Template. Preserve the identifiers needed to match existing rows, even when optional columns are excluded.
Upload updates matching rows without recreating them, adds new rows only when existing table rules permit creation, and retains omitted rows. Match within the current document and table, never by spreadsheet position or item description. Preserve advance-source identity across recalculation, because advance rows are rebuilt during validation.
Apply existing permissions, document editing restrictions, protected fields, contract-item links and advance-source rules. Recalculate dependent amounts using the existing document logic. Upload changes remain unsaved until the user saves the document.
Reject invalid templates, duplicate or foreign row identifiers, invalid values and prohibited changes with row/column guidance. A rejected upload must leave the form unchanged.
